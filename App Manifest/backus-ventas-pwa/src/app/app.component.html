Auditoría y Arquitectura Técnica PWA

Especificación de estándares y estado en tiempo de ejecución para evaluación académica.

Web App Manifest

Archivo manifest.webmanifest que define identidad, iconos y experiencia standalone.

  • ✓ Nombre: Backus Ventas PWA
  • ✓ Short Name: Backus
  • ✓ Display: Standalone (modo app nativa)
  • ✓ Theme Color: #061838 (Navy Corporativo)
  • ✓ Iconos: 8 resoluciones (72x72 hasta 512x512)

Service Worker

Trabajador en segundo plano para interceptar peticiones de red y habilitar funcionamiento offline.

  • ✓ Tecnología: @angular/service-worker (ngsw)
  • ✓ Estrategia Assets: Performance (Cache-First)
  • ✓ Estrategia API / Datos: Freshness con fallback a Cache
  • ✓ Instalabilidad: Evento beforeinstallprompt capturado

IndexedDB Local Storage

Base de datos transaccional NoSQL para persistir órdenes cuando no hay red disponible.

  • ✓ Database: backusVentasDB (v2)
  • ✓ Object Store: pedidos (clave id autoincremental)
  • ✓ Capacidad: Almacenamiento estructurado de pedidos
  • ✓ Sincronización: Cola FIFO para envío a servidor

Cache Storage API

Contenedor de caché para recursos estáticos y respuestas JSON de catálogo.

  • ✓ JSON Catálogo: assets/data/catalogo.json
  • ✓ Fuentes & CSS: Google Fonts y bundle compilado
  • ✓ Resiliencia: Carga instantánea con o sin Wi-Fi

Flujo Operativo Offline-First Backus PWA

Paso 1

Consulta Catálogo

El SW busca en caché local primero; si hay red, actualiza en segundo plano.

➔
Paso 2

Generación de Pedido

El vendedor selecciona productos y arma el carrito en la bodega del cliente.

➔
Paso 3

Persistencia Offline

Si no hay cobertura, el pedido se resguarda en IndexedDB.

➔
Paso 4

Sincronización Cloud

Al reanudar conexión, los pedidos pendientes se sincronizan al ERP central.
